## Blocker

### QA-001: Every list-backed dashboard page returns 404; admin meta fails server-side
- **Area:** dashboard
- **URLs:**
  - Lists that 404 with "Something went wrong":
    - `/dashboard/platform/orders` and `/dashboard/platform/products` (plus `/products/create`)
    - `/dashboard/platform/markets`, `/regions`, `/regions-management`, `/countries`, `/currencies`
    - `/dashboard/platform/discounts`, `/gift-cards`, `/price-lists`, `/invoices`
    - `/dashboard/platform/shipping`, `/shipping-options`, `/shipping-providers`, `/payment-providers`
    - `/dashboard/platform/users`, `/business-account-requests`, `/claims`
    - `/dashboard/platform/product-categories`, `/product-collections`, `/system`
  - Every generic list, for example `/dashboard/products`, `/dashboard/orders`, `/dashboard/specimens`, `/dashboard/listings`. This includes every desk "Open list" button, status count pill and row link.
  - `/dashboard/platform/api-keys` shows "Invalid List".
  - `/dashboard` shows "No lists configured. There are no data models configured in your admin interface."
  - The sidebar **Models** group expands to nothing.
- **Steps:** sign in as the QA admin and open any of the URLs above. It happens both before and after onboarding, and on repeated reloads.
- **Expected:** the lists, home model cards and Models menu render.
- **Actual:**
  - The `(admin)` layout and pages get `adminMeta = null`, because `getAdminMetaAction()` returns `success: false`.
  - `getListByPath()` then returns `undefined`, so `notFound()` runs.
  - The browser console shows "Dashboard operation failed (details redacted)".
- **Evidence that the schema is fine:**
  - The exact `KsFetchAdminMeta` query from `getAdminMetaAction.ts` succeeds when posted to the public `/api/graphql` with the same `keystonejs-session` cookie: HTTP 200, 131 lists, about 818 KB, no `errors`, 0.5 s.
  - Without the cookie it returns "Unexpected error." at `keystone.adminMeta`, which is expected.
  - So the failure is in the server-side self-request (Next server → its own public URL via `getBaseUrl()` → `graphql-request`), not in the schema.
  - Small `keystoneClient` queries from the same server do work (Store settings, Analytics, desks).
  - The response size is the leading suspect: 131 lists here, against far fewer in E-commerce, whose `features/dashboard` code is byte-identical.
- **Likely files:**
  - `features/dashboard/actions/getAdminMetaAction.ts` (`getCachedAdminMeta`)
  - `features/dashboard/lib/keystoneClient.ts`
  - `features/dashboard/lib/getBaseUrl.ts`
  - `app/dashboard/(admin)/layout.tsx`
- **First step:** check the Railway logs for `Failed to fetch admin meta` / `Error fetching GraphQL data`, which `safeErrorSummary` prints.

### QA-002: "Add to cart" silently does nothing; `updateActiveCart` throws
- **Area:** storefront
- **URL:** any product, for example `/us/products/1881-silver-dollar` or `/us/products/1977-championship-final-ticket`
- **Steps:** as a guest or a signed-in customer, click **Add to cart**.
- **Expected:** the line item is added, the header cart count becomes 1, and the cart page lists the item.
- **Actual:**
  - The server action POST returns 200 and a `_openfront_cart_id` cookie is set, but the cart stays at 0 and `/us/cart` says "Your cart is empty".
  - There is no error message anywhere.
  - Calling `updateActiveCart` directly with the real cart id from the signed cart proof (`{ lineItems: { create: [{ productVariant: { connect: { id } }, quantity: 1 }] } }`) returns `"Unexpected error."` at `path: ["updateActiveCart"]`.
  - The variant is published, `inventoryQuantity: 1`, `manageInventory: true`. `activeCart` for the same id resolves fine, so the cart-access check passes.
- **Impact:** no customer can buy anything, so the whole checkout, payment and order flow is blocked.
- **Likely files:**
  - `features/keystone/mutations/updateActiveCart.ts` (differs from E-commerce: `normalizeActiveCartInput` DTO, `paymentCollection: { disconnect: true }` on a cart that has none)
  - `features/keystone/security/active-cart-input.ts`
  - `features/keystone/models/Cart.ts` (`beforeOperation`)
  - `features/keystone/models/LineItem.ts` (`afterOperation`)
  - Any collectibles inventory-unit or reservation hook on line-item create
  - The UI side: `features/storefront/lib/data/cart.ts:530` `addToCart` returns the error as a string, and the product actions ignore it. A failure should be shown to the shopper.

## Major

### QA-003: Price sort shows "0 items" on every browse page
- **Area:** storefront
- **URLs:**
  - `/us/store?sortBy=price_asc` and `?sortBy=price_desc`
  - The same sorts on `/us/categories/*` and `/us/collections/*`
- **Steps:** on All items, choose **Price low to high**.
- **Expected:** 7 items, cheapest first.
- **Actual:** "0 items / No items here yet".
- **Cause:**
  - `getProductsSortedByPrice` upper-cases the country code (`US`) and then looks up `region.countries.some.iso2 = 'US'`.
  - Countries are stored lowercase (`us`, `ca`, `de`), so the region is never found and the resolver returns `{ products: [], count: 0 }`.
  - Verified with a direct query: `count: 0` for both `"us"` and `"US"`. E-commerce passes the code through unchanged.
- **File:** `features/keystone/queries/getProductsSortedByPrice.ts:44` (normalise to lowercase, or compare case-insensitively at `:64` and in the variant price filter at `:128`).
