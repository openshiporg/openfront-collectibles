## Blocker

### QA-020: Cart `total` / `rawTotal` / `tax` throw for any cart with items, so no order can be placed anywhere
- **Area:** storefront and dashboard
- **URLs:** `/us/cart`, `/us/checkout`, `/dashboard/platform/orders/create`
- **Steps:**
  1. **Storefront:** open `/us/products/1881-silver-dollar` and click **Add to cart**.
  2. **Admin:** open Create order, add 1881 Silver Dollar, pick customer `QA Order` and their address, then **Create Cart**. Choose **Charge now** with "Manual review", then **Place Order**.
- **Expected:** the cart shows the item and its totals, checkout proceeds, and the order is created.
- **Actual:**
  - The line item **is** saved: `carts { lineItems { quantity } }` returns 1. But querying the cart fails:
    - `activeCart(cartId)` (storefront, with the cart proof header) → `"Unexpected error."` at `path: ["cart","total"]`.
    - On the admin cart `cmvlmstrl000kqi010c0tzkkj` (admin cookie):
      - These resolve: `subtotal` = "$195.00", `shipping` = "$18.00", `rawSubtotal`.
      - These fail with `Unexpected error.`: `total`, `rawTotal`, `tax`.
  - **Storefront:** the cart and every other page crash (QA-021).
  - **Admin:** Place Order logs `Error placing order: Error: Unable to complete the request` and no order is created. `orders` stays empty.
- **Cause:**
  - The `total`, `rawTotal` and `tax` resolvers in `features/keystone/models/Cart.ts` (`total` ≈ line 546, `rawTotal` ≈ 609) select `region { taxRate currency { code noDivisionCurrency } }`, **without `id`**.
  - They pass that projection to `calculateCartSubtotal` (line 26), which throws `'Cart currency is unavailable'` when `!cart.region?.id` (line 32).
  - `subtotal` works because its projection includes `region { id … }`.
  - Empty carts return early at line 30, before the guard, which is why round 1 didn't see it. `updateActiveCart` failing earlier masked it too.
- **Fix:** add `id` to the `region { … }` selection in every pricing projection in `Cart.ts` (`total`, `rawTotal`, `tax`, and any other resolver that calls `calculateCartSubtotal`/`calculateCartTax`/`calculateCartTotal`). Or have the helpers re-fetch the region. Then check `completeActiveCart`, `placeOrder` and `Order` creation, which read the same totals.
- **Note:** E-commerce's `Cart.ts` has the same guard at line 32 and the same `total` projection. Check it there too.
- **Impact:** no customer or merchant can complete a sale. Checkout, Stripe or manual payment, order confirmation, order history, the order detail and fulfilment screens, High-Value Fulfillment and invoices all stay untested on real data.

## Major

### QA-021: One failing cart query takes down every storefront page (React #441 server error)
- **Area:** storefront
- **URLs:** `/us`, `/us/store`, `/us/products/*`, `/us/cart`, `/us/checkout` (500)
- **Steps:** add any item to the cart (QA-020), then open any page.
- **Expected:** if the cart can't be loaded, the page still renders, with an empty or unavailable cart and a message.
- **Actual:**
  - Every page shows "This page couldn’t load · A server error occurred" and logs `Minified React error #441`. `/us/checkout` returns HTTP 500.
  - The shopper is locked out of the whole shop until the `_openfront_cart_id` cookie is cleared by hand. Clearing it restores the site.
- **Cause:** in `retrieveCart()` (`features/storefront/lib/data/cart.ts:29-33`), the catch calls `removeCartId()`, which runs `cookies().set(...)`. That runs during a Server Component render (header cart button, cart page, checkout). Next.js only allows cookie writes in Server Actions and Route Handlers, so the "graceful" fallback throws itself.
- **Fix:** in render paths, return `null` without touching cookies. Clear the stale cookie from a server action, a route handler, or `proxy.ts`. The product page should also surface `addToCart` failures, as round 1 asked; today the page crashes before the new "Could not add this item" message can show.
- **File:** `features/storefront/lib/data/cart.ts:18-34`, `features/storefront/lib/data/cookies.ts` (`removeCartId`).
